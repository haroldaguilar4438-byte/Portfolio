04 — Problem-Solving Portfolio

How I debug under pressure.

Each case follows the same trail: symptoms → investigation → root cause → solution → lesson.

Symptoms: Login succeeded but the next page showed the user as logged out. Investigation: Reproduced twice, checked session values with a debug dump, confirmed the redirect ran before any session write. Root cause: Missing session start on the landing page. Solution: Added it consistently and re-tested login → dashboard → logout. Tools: Browser DevTools, PHP error log. Lesson: Verify shared setup (sessions, includes) on every page, not just the login handler.

Investigation

Narrowed the viewport in DevTools, found a fixed-width card forcing horizontal scroll. Tools: responsive mode, element inspector.

Solution & lesson

Switched the grid to flexible columns with wrap. Now I check small screens first, not last.

Symptoms: Record list took seconds to render. Investigation: Counted rows returned — the query fetched everything with no limit. Root cause: No pagination or search filter. Solution: Added LIMIT-based pagination and a name search. Tools: MySQL client, timing checks. Lesson: Never render unbounded query results.

Symptoms: XAMPP showed a port-80 error on start. Investigation: Read the control-panel log, checked which app held the port. Root cause: Another program occupied port 80. Solution: Stopped the conflicting app and restarted; noted the config alternative. Tools: XAMPP logs, Task Manager. Lesson: Read the log first — it usually names the cause.

Symptoms: Push failed with a non-fast-forward error. Investigation: Compared local and remote history — the remote had commits I lacked. Root cause: Tried to push without pulling first. Solution: Pulled, resolved one small conflict, pushed cleanly. Tools: Git log/status, GitHub. Lesson: Pull before push; commit early and often.

06 — Responsible AI Literacy

AI assists. I own the outcome.

AI supported drafting, debugging, and learning — never replaced my judgment. Every AI suggestion was verified by reading docs, testing code, and re-checking logic.

How I use AI responsibly

  • Tools: ChatGPT and Copilot — only what I actually used
  • Used for: explaining errors, drafting boilerplate, SQL help, docs summaries
  • Done by me: architecture, final code, testing, security checks, writing
  • Verification: ran the code, read official docs, tested edge cases
  • AI mistakes caught: suggested a JavaScript method that didn't exist → fixed by checking MDN; drafted a query with string concatenation → rewrote with parameters

My verification rule

“If I can’t explain it and test it, I don’t ship it — no matter who drafted it.”

10 — Final Reflection

What building this taught me.

When I started this portfolio, I thought the goal was to list what I know. I finished understanding that employers look for how I think: how I break down a problem, how I verify my work, and how honestly I describe what I can and cannot do yet. Each project below replaced with real work taught me more than any tutorial — especially the parts where something broke and I had to investigate instead of guessing.

The most valuable skill I developed was not a framework. It was documenting decisions: what I tried, what failed, and what I would change next time.

Working with databases showed me that design decisions outlive code. A clear schema, validated inputs, and controlled access prevent entire classes of bugs and security issues. Studying defensive security — hashing, prepared statements, least privilege — changed how I write even small features. I now treat every form and query as a trust boundary.

Using AI responsibly shaped my process as well. AI helped me draft boilerplate, explain unfamiliar errors, and explore alternatives faster. But it also produced confident mistakes: invented methods, insecure patterns, and vague explanations. I learned to verify everything against documentation and tests, and to keep a log of what AI suggested versus what I finally shipped. AI made me faster; verification made me reliable.

I still need to improve in deeper JavaScript, testing discipline, and explaining trade-offs clearly in interviews. My next professional goal is earning an internship where I can ship reviewed code with a team, and this portfolio is my commitment to getting there with honest, verifiable work.
